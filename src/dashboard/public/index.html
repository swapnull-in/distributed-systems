The fiber-cut drill

Three regions, each running at the same utilization. Kill one — the survivors must absorb its load with capacity that already exists.

Set a utilization, then cut a region.

The proof: with 3 active regions, each must run at ≤ 66% so a survivor peaks at ≤ 100% (each takes 1.5× its load). That “idle” third isn’t waste — it’s the RTO insurance premium. Cut it to save money and the next region loss is an outage. Autoscaling can’t save you: cold-start stampede on the cloud’s worst day.

The proof: naive retries turn a 3-round dip into a permanent outage — retries become the load, so even after capacity returns the useful work stays near zero (a stable-but-broken equilibrium). A retry budget caps the amplification and the breaker sheds load so the dependency can recover.

The proof: LWW keeps one replica’s value by timestamp and silently drops the other’s writes — a data-loss policy wearing a tie-breaker’s clothes (fine for presence, indefensible for a cart). An OR-Set merges by union: every concurrent add survives, in any order. The limit to say out loud: “reserve exactly one of N” doesn’t commute — that needs consensus or region-homing.
